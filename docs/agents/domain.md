# Domain docs

Pilot uses one domain context. Read the root [GLOSSARY.md](../../GLOSSARY.md) and any relevant ADRs in `docs/adr/` before exploring the area. If no ADRs exist yet, proceed.

Use glossary terms in specs, tasks, design notes, and tests. If a term is missing or ambiguous, resolve it through domain modeling. If a proposal conflicts with an ADR, cite the ADR and explain the conflict.

Record a decision only when it is hard to reverse, surprising without context, and involves a real trade-off. Name each ADR `docs/adr/NNNN-slug.md`, using the next number. State the context, decision, and rationale. When a later ADR replaces one, link the old record to its successor. Create the directory with the first ADR.
