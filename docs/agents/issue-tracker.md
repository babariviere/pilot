# Issue tracker: Pilot

Pilot is the source of truth for planned work. A mission holds the brief and agreed spec; its tasks track implementation, dependencies, and progress.

- **Fetch work:** Open the referenced mission or task in Day, or use the `mission` tool when it is available for that mission. Ask for the mission or task reference if it is missing.
- **Publish work:** Add the agreed spec to the mission plan and proposed implementation work as tasks. Use the [Day planning flow](../missions.md) or the `mission` tool actions allowed for your role. If you cannot publish, give the user a draft for Day. Publishing a plan does not authorize starting work.

Keep proposals, progress notes, and verification evidence with the relevant mission or task.
