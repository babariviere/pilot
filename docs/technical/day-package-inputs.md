# Source-matched Day package inputs

`apps/desktop/scripts/day_build_inputs.py` builds inputs for the existing
`bundle_runtime` assembler. It does not sign, notarize, archive, release,
install, register or start an app or service. The shipping desktop selection
and legacy apps are unchanged.

## Recipe

The input is a full immutable Pilot commit, not a working tree or bookmark.
The builder extracts Git objects into a fresh private directory, then:

1. Checks the native macOS arm64 host, installed Rust/Cargo 1.99.1,
   mbx 1.26.0 and official Longbridge NSH 0.4.0. The installed CLI checksum
   is pinned. Day's lock must select only release e626a8dd NSH crates and
   must not contain GPUI. There is no CLI-build or source-patch fallback.
2. Builds Day's own `pilot-desktop`, with `macos-host`, and the existing
   `pilot-desktop-update-helper`, with `native-macos`. Cargo JSON identifies
   each actual output. There is no renamed stock runner.
3. Builds the required existing `pilot-visual-worker` in an isolated
   workspace, using its unchanged sources/dependency versions and the
   desktop lock as a seed. Adding `[workspace]` isolates it from GPUI;
   Cargo prunes the seed offline, and every resolved package version/source/
   checksum must be present in that seed. Builds then use `--locked`.
   The resulting manifest and lock digests are recorded. The pinned QuickJS-NG
   0.17.0 archive is supplied separately and checksum-checked by the
   existing extractor. This builder never downloads it.
4. Runs the installed CLI's **build**, not package/run, for `Connected.tsx`.
   A snapshot-only `nsh.json` uses the fixed app ID and exact `Bridge::METHODS`
   host grant. The development/mock config is not edited. The guarded Day
   launcher seeds the genuine released runner lock. No package-manager
   lifecycle hooks or automatic package-manager switching run.
5. Copies the complete generated bytecode, JS/maps, capabilities, app ID
   and assets to `nsh/`. Unexpected files, links, dynamic chunks, widened
   capabilities, missing files and changed copies are refused. The bootstrap
   disables runtime-delivered chunks. `gui-resources.json` binds the full
   inventory to the executable digest, immutable source, target and release.

Cargo is offline, with one job, no incremental compilation and no debug
information. All writable targets and caches must be private and drained
before reuse. Ambient trust, provider/discovery credentials, compiler wrappers,
NSH resource overrides and package-manager configuration are not inherited.
Missing dependencies fail, rather than installing or repairing shared state.

## Receipts and trust

Both app and helper expose only the exact single diagnostic argument
`--build-input-receipt`. It exits before startup, AppKit, service or update
work. The linked updater dependency reports its compiled source, recipe,
target, profile, compiler identity and updater configuration. The builder
compares both reports with the actual build selections and rejects any
difference. Binary hashes, genuine Cargo artifact messages, tool hashes,
connected config and the isolated worker manifest digest are also kept.

The default lane deliberately compiles **unconfigured** trust. Its receipts
say `development-rust-inputs`, and `installable_update` is false. The existing
bootstrap still refuses missing compiled trust. A diagnostic report is not
a signature, `ExpectedTarget`, READY/COMMIT, startup acknowledgement or proof
that a package is installed.

`--production` requires the existing explicit public updater configuration
and approved distribution-policy setting through `gui_release.configuration`.
It builds the optimized release profile and compares the actual compiled
configuration in both binaries. It neither creates a key nor accepts test
keys as production evidence. Even configured inputs say
`installable_update: false`: a signed payload and its independent manifest
are still required. Missing production configuration/payload is unavailable,
not a successful update.

## Entry points

Prepare private dependencies/tools separately. The builder never bootstraps
them. Use absolute qualified tool paths and private directories:

```sh
export NSH_DAY_CLI=/absolute/installed/longbridge/nsh
export NSH_DAY_MBX=/private/build/bin/mbx
export NSH_DAY_REAL_CARGO=/absolute/installed/toolchain/bin/cargo
export RUSTC=/absolute/installed/toolchain/bin/rustc
export CARGO_HOME=/private/build/cargo-home
export CARGO_TARGET_DIR=/private/build/target
export MBX_CACHE_DIR=/private/build/mbx-cache
export PILOT_DAY_QUICKJS_ARCHIVE=/private/build/quickjs-ng-0.17.0.tar.gz
python3 apps/desktop/scripts/bundle_runtime.py rust --gui day \
  --source FULL_COMMIT --output /private/build/day-inputs
```

The same implementation is available directly through `day_build_inputs.py`.
The legacy `rust` default stays GPUI. `assemble(..., gui_resources=inputs / "nsh")`
(CLI: `bundle --gui-resources`) consumes these files in the unchanged trusted
fixed app/helper layout. Assembly signs its output, so it is a **separately
authorized** action, not part of input verification here. App/helper trust
equality, visual-worker, runtime/native-helper receipts, NativePlatform,
signature and ExpectedTarget checks remain required.

## Supported lanes and evidence limits

The implemented input lane is **native macOS arm64 only**, targeting macOS
15.0 or later. macOS x86_64, universal binaries and cross compilation are
unsupported. Linux x86_64/arm64, Windows, iOS, Android, Web and TUI have no
Day production input recipe here. Their existing updater/platform policies
must not be treated as Day package qualification.

Portable tests use private synthetic tools/resources and test fail-closed
recipe, artifact, receipt and resource rules. They do not execute fixture
bytecode or admit fixture signatures. Native checks are hidden build-only
evidence, not visible UI, installed-payload, signing or release acceptance.
Production signed payloads and joined automatic-update acceptance remain
unavailable until separately supplied and qualified.
