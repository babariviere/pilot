## Fixture and acceptance discipline

Use isolated temporary stores, faux providers and deterministic held-response/async gates at real ownership boundaries. Release each owned gate, child, subscription, socket and writer and await teardown even on failure. Do not fix failures with retries, longer sleeps, disabled assertions or skips. Inject before and after durable admission and observe disk/receipt, not only mocks or UI state. Assert exact immutable intent, operation identity, target, host/lineage and newer editable text. Assert FIFO mutation order and no second Store writer.

A baseline-negative control must fail the old behavior for the intended reason and pass the changed behavior. If temporarily restoring source, verify bytes, force recompilation as needed and verify the test census: preserving timestamps can reuse a stale binary. Record exact revision, command, dependencies, result, skips and runner limits. Synthetic transports expose ordering faults but do not prove native input, UI frames, actual process lifecycle or a deployed installation. Native and integration qualification must exercise the relevant real boundary.

## Evidence classification

The original synthesis performed static source/document inspection and cheap Markdown/link checks only, with no builds, test suites, installs, live-user probes or CI triage. #20's 14 and #23's 12 focused tests were builder-reported using sibling dependencies; neither demonstrates a standard installed suite, and typecheck was blocked. For #23, coordinator-reviewed real HTTP/SessionManager fixture evidence reaches admission/startup spans, not a real kernel/native journey; attached inputs were empty and recovery was a direct fresh-journal handler, not a full server boot. #21/#22 scoped Rust/Clippy and negative-control results were builder-reported and coordinator-reviewed; ignored tests and native/full-suite gaps remain. #24 landed after coordinator review with builder-reported scoped checks and a baseline-negative control; native/full-suite gaps remain.

Later maintenance reconciles delivered #26 (68 interaction passes/1 pre-existing ignored, three catalog controls included) and #27 (48 client/46 model passes, 0 ignored), their production Clippy/format and restored-source negative controls from builder reports, not new native or full-suite execution. #28 directly ran its dependency-free focused Node file on macOS/Node 24: 17 passes, no skips, actual worker/SQLite/isolated-child lifetimes plus synthetic IPC/error/gate controls, separate from complete daemon/native terminal/kernel lifecycle. The faithful old-order omission control fails; restored source is byte-verified and rerun with matching census. A combined run also passes all 23 existing `schedules.test.ts` controls using a temporary same-lockfile sibling dependency resolver, not a standard installed workspace. Changed-file Biome and whitespace pass; standard whole-project typechecking is blocked by missing local Node type definitions. Full suites, exact-head CI and deployment remain unverified. See [roadmap](roadmap.md) for the bounded contract and existing entered-validation/HTTP-drain limit. Earlier sampled CI evidence and old artifact revisions remain historical, not current failures or passing gates.
